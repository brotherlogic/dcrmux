# DCRMux

So we have some the github.com/brotherlogic/devcontainer-manager which handles all our dev containers and agy instances. We have the dcr command line utility which mediates between our terminal and the container manager. So we type dcr <repo> <issue> and this takes us into a session where we can resolve a given issue. So usually we're working off an issue tree and either doing some deep dive into a spec, or resolving some kind of issue with a PR

DCRMux is putting all of this together into one view so we don't have to maintain our context outside of this. Typically how I run dcr sessions, is that I find the issue / issues I'm working on and then work through the given issue tree for that high level issue, and work on individual leaves on that tree. So we'd split the window into three panes: a full left pane showing the next issue or pr container for each issue tree (assuming that older issues are blocking newer ones in the leaves of a tree), a top right pane showing a summary of the issue in a couplr of paragraphs and then the bottom right pane which hosts the ssh window into the container, where I'm having the conversation with the agent.

So the bottom right window is larger than the top right since that's where we're mostly working. And the leftmost pane dynamically updates when the state changes - so when we close out an issue in github, it adjusts the display, and if we've been on e.g. issue 5 and it's now closed and issue 6 is next, it automatically bumps us to issue 6. We can use my internal brotherlogic/ghwebhook system to get github updates.
